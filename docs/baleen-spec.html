Baleen

by Walking Whale

Turn legacy archive files into archival formats, and prove that every one of them is sound.

Approved for implementation Apache-2.0 macOS + Windows Offline · portable walking-whale-baleen
TL;DR
  • Baleen walks a folder tree and converts every non-archival file into one of five archival formats: JPEG, TIFF, PDF/A, MP4, M4A.
  • Every output, and every file that was already archival, is verified (full decode, PDF/A validation, full media decode) and recorded with SHA-256 in a CSV report.
  • The source folder is never modified. Output goes to a separate folder that mirrors the source structure.
  • Runs from a portable folder on a clean Mac or Windows machine: double-click to start, delete the folder to uninstall. No installer, no network.
  • Files are processed in parallel across the processor cores, within limits the user sets in Settings (Gentle / Balanced / Maximum).
  • A left rail with workflows (Convert, Check), Runs history and system pages. Every run gets one page that shows live progress, then the results.

01 · Background & goals

Why Baleen exists

Small archives and collections inherit born-digital material from the 2000s: camera clips in AVI and MPG, Word .doc files, e-mails saved as .eml, BMP scans, WMA recordings. Long-term preservation and access need a small set of open, well-supported formats, plus evidence that each file is intact. Staff usually have a laptop and a NAS share, no IT support, and no time to learn command-line tools.

Baleen was first scoped for an art archive digitising event documentation from 2000–2005: about 1,700 files and 1 GB, of which 63 needed conversion (Appendix D). It is built generic and released as open source.

Baleen whales filter whatever the sea brings and keep what sustains them. This tool does the same with a folder.

03 · Principles

Non-negotiables

Every requirement below derives from these. When behaviour is unclear, the principle wins.

P1
Source is read-only

Baleen MUST NOT create, modify, rename or delete anything under the source root, including lock or temp files.

P2
No overwrite

An existing file in the output root is never replaced.

P3
No silent guessing

When a human decision is needed (uncertain encoding, multi-frame image, name clash…), the file is flagged NEEDS_REVIEW with a reason code.

P4
Only checked files land

An output that fails a check is never placed. An output whose check could not run is placed but flagged (DR-09).

P5
Atomic placement

Work locally and verify, publish to the output as a .part file, confirm its hash, then rename into place on the same volume. A crash never leaves a partial file under a final name.

P6
Per-file isolation

One file's failure never stops the run.

P7
Deterministic

Same source tree, settings and tool versions give the same plan and the same output names.

P8
Offline & private

No network access at runtime: no telemetry, no update checks, no fetching remote content referenced by documents or e-mails.

P9
Everything accounted for

Every scanned file and every extracted attachment appears exactly once in the report, whatever its status.

05 · Processing pipeline

Seven steps per run

  1. Validateroots exist, no overlap, output writable
  2. Scanwalk source, ignore system files
  3. Planroute and output name for every file
  4. Stagecopy to the local work folder while hashing
  5. Convertin parallel lanes, on the local copy
  6. Verifychecks V-* on the staged output
  7. Publish & report.part, read-back hash, atomic rename

5.1 Validate roots

  • Source exists and is readable. Output is created if missing; it may already contain files.
  • Output MUST NOT equal the source, be inside it, or contain it. Compare resolved real paths, case-insensitively on macOS and Windows.
  • A lock file <output>/_baleen/.lock (PID + hostname + start time) prevents two instances writing to the same output root. A stale lock (process gone) is replaced after a warning.

5.2 Scan

  • Recursive walk. Entries are sorted by NFC-normalised, case-folded name so the order does not depend on the filesystem.
  • Symlinks and junctions are not followed. Symlinked files and directories are listed as IGNORED SYMLINK.
  • System files are listed as IGNORED SYSTEM_FILE: .DS_Store, ._*, Icon\r, Thumbs.db, ehthumbs.db, desktop.ini, ~$*, .~lock.*#, and the folders $RECYCLE.BIN, .Trashes, .Spotlight-V100, .fseventsd, @eaDir, #recycle, .@__thumb, _baleen, .baleen-staging. Their contents are not entered.
  • Other dotfiles are processed normally (DR-20).
  • For each file, record the relative path (always / separators), size and mtime.

5.3 Plan

Classify each file by lower-cased extension (§6) and compute its output path (§7). The full plan exists before any write; UI-C4 Preview displays it.

5.4 Item flow

Each item moves through four steps. Steps of different items run at the same time in the lanes of §5.5.

  1. Stage (Files lane):
    • Re-stat the source. If size or mtime changed since the scan → FAILED SOURCE_CHANGED.
    • Check work-folder space (§5.5).
    • Copy the source into the local work folder, <work>/<run-id>/<n>/input.<ext>, computing SHA-256 in the same read pass. Converters MUST only touch this copy. This keeps LibreOffice lock files and odd path characters away from the source (P1).
    • If the final output path already exists, apply §7.5 and skip to Report.
  2. Convert & verify (the lane for the item's category): convert inside the work folder (or pass through, for copies), then run the §8 checks on the local result. PDF/A validation happens in the PDF/A lane, in batches.
  3. Publish (Files lane):
    • Copy the verified result to <output>/.baleen-staging/<run-id>/<n>.part.
    • Read it back to confirm its SHA-256 (V-HASH).
    • Re-check that the final path is free, then rename into place (same volume, atomic).
    • Set the output mtime to the source mtime.
  4. Report: commit the result to the run journal (§10.4), then delete the item's work and staging files.
  • Check-only items (check-only setting, or Check mode) use the same lanes but skip Stage and Publish. The source is verified in place, read-only, and hashed by streaming; nothing is written.
  • Why work locally: decoding, LibreOffice and veraPDF run against a fast local disk, not the network. A converted file still crosses the network three times (read source, write output, read back for V-HASH), but nothing is decoded over the network.

5.5 Parallel lanes & resource limits (DR-32)

One job runs at a time, but its items are processed in parallel across four lanes. A dispatcher starts the next task, in plan order, whenever its lane has room and the task's needs fit inside three budgets. The user sets the budgets in Settings › Resource use (§11, UI-S2).

  • Accounting: at all times, tokens in use ≤ B, reserved memory ≤ M, and transfers ≤ T. A single task that needs more than a budget (e.g. a huge image) runs alone once nothing else is running.
  • Order: within a lane, tasks start in plan order. Items may finish out of order; the report is still written in plan order (§10.1).
  • Live changes: a changed resource setting applies at the next dispatch, including during a run. Running tasks are never interrupted. If usage is above a lowered limit, nothing new starts until it drops.
  • LibreOffice batches:
    • Each Documents instance has its own profile, data/lo-profile-<k>.
    • An instance converts up to 8 files per soffice --convert-to call. Files in one call share an import filter (§6.2) and have unique staging names, so outputs map back to inputs.
    • Batch timeout: 60 s + 30 s per file.
    • If a batch fails or times out, its files are retried one per process with the 300 s per-file limit, so one bad file cannot sink its neighbours.
    • Measured: 12 documents took 1.37 s each with one process per file, and 0.12 s each in one call (DR-35).
  • veraPDF batches: PDFs waiting for validation are grouped by flavour and validated in one JVM per batch. A batch closes at 25 files, after 10 s of waiting, or immediately when nothing else is left. Results are matched per file from the batch report. If a batch run crashes, its files are revalidated one by one.
  • FFmpeg threads: every FFmpeg call gets an explicit -threads equal to the tokens it holds, so encodes never exceed the processor budget.
  • Work-folder space: before staging an item, the work folder needs at least 2 × the item's size + 1 GB free. Otherwise wait for running items to finish. If nothing is running and space is still short → FAILED NO_WORK_SPACE.
  • Lower priority (low_priority, default on): Baleen's worker threads and every process it starts run below normal priority. The user's other apps go first, and idle cores are still used fully.
    • macOS: per-thread QoS utility via pthread_set_qos_class_self_np; child processes start at nice +10.
    • Windows: THREAD_PRIORITY_BELOW_NORMAL; children start with BELOW_NORMAL_PRIORITY_CLASS.
    • Applied per task, so toggling affects tasks started afterwards.
  • Keep awake (keep_awake, default on): while a job runs, Baleen prevents idle sleep, and releases it when the job ends.
    • macOS: caffeinate -i -w <pid>.
    • Windows: SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED).
    • Closing a laptop lid can still sleep the machine; the UI says so.
  • Provenance: the run JSON records cores, RAM, the resource settings and the resolved B, M, T, K, F at start, plus every change made during the run.

5.6 Cancel & crash

  • Cancel stops dispatching. Tasks already running finish, including LibreOffice batches and FFmpeg encodes. Remaining items then get SKIPPED CANCELLED, and the report and run JSON are written. The UI shows "Stopping after n files in progress…".
  • Crash recovery: on start, Baleen finalises any run that has a journal but no report. It writes the report from the journal, marks unprocessed items SKIPPED INTERRUPTED, and marks the run Stopped. Stale work and staging folders (Baleen-owned only) are removed. A re-run resumes per §7.5.
  • One job at a time per Baleen instance; the output lock (§5.1) also stops two instances writing one output root.

6.1 Images (Pillow)

  • Image.MAX_IMAGE_PIXELS is raised to 1,000,000,000 so large archival scans open. Sources are local files the user chose.
  • JPEG / TIFF content: byte copy after V-IMG; never re-encoded (DR-16).
  • Other images: more than one frame → NEEDS_REVIEW MULTI_FRAME_IMAGE. Alpha (RGBA, LA, PA, or a transparency key), more than 8 bits per channel (I;16*, I, F), or CMYK → TIFF with LZW compression, ICC kept. Otherwise → RGB JPEG, quality 95, 4:4:4 subsampling, optimised, ICC and EXIF kept.
  • Content mismatch: when Pillow's detected format differs from the extension, route by content and add note CONTENT_MISMATCH.
  • A source that needs conversion but cannot be decoded → FAILED SOURCE_UNREADABLE. A JPEG/TIFF source that fails V-IMG → NEEDS_REVIEW SOURCE_INVALID (§8).

6.2 Documents (LibreOffice)

soffice -env:UserInstallation=<file URI of data/lo-profile>
        --headless --invisible --nologo --norestore --nolockcheck --nodefault
        [--infilter=<import filter>]
        --convert-to 'pdf:<export filter>:{"SelectPdfVersion":{"type":"long","value":"<N>"}}'
        --outdir <staging dir>  <staging input>
# export filter: writer_pdf_Export | calc_pdf_Export | impress_pdf_Export
# N: 1 = PDF/A-1b · 2 = PDF/A-2b · 3 = PDF/A-3b      (setting pdfa_level)
# infilter: .txt → "Text (encoded)" with UTF-8 · .html/.htm → "HTML (StarWriter)"
  • Arguments are passed as a list, never through a shell. The private profile lives in data/lo-profile and is initialised on first use.
  • Normally run in batches by the Documents lane (§5.5). A file retried on its own has a 300 s timeout; on timeout, kill the whole process tree → FAILED TIMEOUT.
  • No output or an error exit → FAILED CONVERSION_ERROR. A password-protected document → PASSWORD_PROTECTED.
  • Fonts: system fonts only (DR-15). Substitution is possible and accepted.

6.3 Plain text encoding

  • Certain: a UTF-8 or UTF-16 BOM, or a strict UTF-8 decode that succeeds (pure ASCII counts).
  • Not certain, setting txt_encoding = auto: NEEDS_REVIEW ENCODING_UNCERTAIN; nothing written. The message names the first of big5, gb18030, shift_jis, windows-1252 that decodes strictly, as a hint.
  • Not certain, setting = a named encoding: decode strictly with it. Failure → FAILED ENCODING_MISMATCH.
  • Normalise line endings to LF and write a UTF-8 (BOM) staging copy for import.
  • V-TEXT: non-whitespace characters extracted from the PDF must be ≥ 98% of the source's; otherwise FAILED TEXT_LOSS (usually missing glyphs).

6.4 HTML pages

  • The staging copy is rewritten before import:
    • Remove <script>, <iframe>, <object>, <embed>.
    • Resource URLs using http:, https:, ftp: or // (in src, srcset, background, <link href>, CSS url()) are replaced by visible text [external resource not archived: URL].
    • Anchor links stay as they are.
  • Relative resources (e.g. images beside the page) resolve against the original source folder through an injected <base href>. Read-only access; nothing is created there.
  • Charset comes from the BOM or <meta charset>; otherwise apply §6.3.

6.5 E-mail (.eml)

  1. Parse with Python email (policy.default). Unparseable → FAILED CONVERSION_ERROR.
  2. Render one HTML document:
    1. Headers: From, To, Cc, Date (original string, plus ISO 8601 when parseable), Subject, all RFC 2047-decoded.
    2. Attachments block: each attachment's name, size and saved relative path (or "not saved", per policy).
    3. Body: the text/html alternative if present, sanitised as in §6.4; otherwise text/plain, preformatted with wrapping. cid: images become [inline image: name, saved as attachment] and are handled as attachments.
  3. Charset: decode the body strictly with the declared charset. On failure, decode with replacement characters and flag NEEDS_REVIEW CHARSET_ERRORS. The output is still written.
  4. hide_email_addresses: every e-mail address in headers and body is replaced by [address hidden]; display names are kept.
  5. Convert the HTML with LibreOffice (§6.2, HTML import filter).

6.6 Existing PDFs

  • Encrypted → NEEDS_REVIEW PDF_ENCRYPTED.
  • Read XMP pdfaid:part and pdfaid:conformance. No PDF/A claim → NEEDS_REVIEW NOT_PDFA; not copied.
  • Claimed → validate with veraPDF at the claimed flavour. Pass → OK (copied if copy_existing). Fail → NEEDS_REVIEW PDFA_INVALID; not copied.
  • Any valid PDF/A flavour is accepted; pdfa_level applies only to new conversions (DR-07).

6.7 Audio & video (FFmpeg)

  • Probe: ffprobe -v error -show_format -show_streams -of json. Failure → FAILED SOURCE_UNREADABLE.
  • Classify streams: video streams with disposition.attached_pic = 1 are cover art, ignored and dropped. A real video stream → video route; otherwise audio streams → audio route; neither → UNSUPPORTED NO_MEDIA_STREAMS. Subtitle and data streams are dropped, with note STREAMS_DROPPED.
  • Video → .mp4:
    • Already MP4, video in {h264, hevc} and audio in {aac, mp3} → byte copy (or check).
    • Same codecs in another container → remux with -c copy.
    • Otherwise transcode video with libx264 -preset slow -pix_fmt yuv420p: CRF 18 (high) or CRF 23 (standard). Odd dimensions are padded with pad=ceil(iw/2)*2:ceil(ih/2)*2 (no resampling). Frame rate and interlacing are untouched.
    • Audio: copied if aac or mp3; otherwise AAC at 192 kb/s (high) or 128 kb/s (standard), keeping sample rate and channels.
  • Audio → .m4a (or .mp4 per audio_container):
    • aac or mp3 streams are copied into the MPEG-4 container (DR-13).
    • Anything else → AAC at 192 or 128 kb/s.
    • -vn drops cover art.
    • A source already in the target container and extension → byte copy.
  • Always: -nostdin -n -protocol_whitelist file,pipe -fflags +genpts on input; -map_metadata 0 -movflags +faststart -f mp4 on output.
  • Timeout: max(600 s, 10 × duration) → FAILED TIMEOUT.

7.2 Name rule

7.3 Clash rule (DR-05)

  • Scope: clashes are resolved per output directory, over every item planned into it: all supported source files in the mirrored source directory, plus any attachments planned there. This holds regardless of copy_existing or eventual status, so names are stable across settings.
  • Key: the NFC-normalised, case-folded full target name.
  • Suffix: if two or more items share a key, each becomes <stem>_<source ext, lower-case, no dot><target ext>.
  • Unresolved: if keys still collide, every item involved → NEEDS_REVIEW NAME_CLASH_UNRESOLVED.
  • Attachments folder: <final e-mail output stem>_attachments.

7.4 Determinism

The plan depends only on the source listing, audio_container (it changes an extension) and e-mail contents (attachments). Shuffling scan order MUST NOT change any name (tested).

7.5 Existing outputs & resume (DR-18)

If the final path already exists, search prior reports <output>/_baleen/report-*.csv, newest first, for a row matching all of:

  • the same source_path and source_sha256;
  • the same output_path;
  • an output_sha256 equal to the existing file's.

Then:

  • Match: re-run the checks on the existing file. Pass → OK RESUMED. Fail → NEEDS_REVIEW OUTPUT_INVALID. The file is left untouched either way.
  • No match: NEEDS_REVIEW OUTPUT_OCCUPIED; nothing written (P2).

7.6 Timestamps

Output file mtime = source mtime. Directory times are not managed.

7.7 Path limits

On Windows, file operations use extended-length paths (\\?\). Any path component longer than 255 UTF-16 code units → NEEDS_REVIEW PATH_TOO_LONG.

7.8 Sanitising attachment names

Applies only to names from inside e-mails; source names are never changed.

  • Strip path components and control characters.
  • Replace < > : " / \ | ? * with _.
  • Trim trailing dots and spaces.
  • Suffix Windows reserved names (CON PRN AUX NUL COM1–9 LPT1–9) with _.
  • Truncate the stem so the name is ≤ 200 bytes in UTF-8.
  • An empty result → attachment-<n>.

13 · Local server & security

Loopback, token, origin

Any web page the user visits could try to call a local server. These rules make that useless.

IDRule
SEC-1Bind 127.0.0.1 only, never 0.0.0.0. Port: the first free one in 8765–8799, unless BALEEN_PORT is set.
SEC-2Each process generates a 256-bit random launch token.
  • serve opens the browser at /auth?t=<token>.
  • The server sets cookie baleen_session (HttpOnly, SameSite=Strict, Path=/, session lifetime) and redirects to /.
  • The console prints the same URL for re-opening.
SEC-3Every route except /auth and /static/* requires the cookie (constant-time compare). Missing or wrong → 403 page explaining how to open Baleen from the launcher.
SEC-4The Host header MUST be 127.0.0.1:<port> or localhost:<port>; otherwise reject. This defends against DNS rebinding.
SEC-5State-changing endpoints are POST-only. Origin MUST equal the server origin; if it is absent, Referer MUST match; otherwise 403.
SEC-6Response headers:

SEC-7The server accepts absolute paths only and resolves real paths. It reads only inside the source root and writes only inside the output root and BALEEN_HOME/data. "Open / reveal" works only for paths inside those roots.
SEC-8Subprocesses get argument lists only (no shell), explicit tool paths, and a sanitised environment (TMP/TEMP → data/tmp). The whole process tree is killed on timeout or cancel.

14.3 Launchers

  • Working directory: change to the launcher's own folder and set BALEEN_HOME to it.
  • Environment, so all state stays in the folder:
    • TMPDIR (macOS) or TEMP and TMP (Windows) → data/tmp
    • PYTHONNOUSERSITE=1, PYTHONDONTWRITEBYTECODE=1
    • JAVA_TOOL_OPTIONS=-Djava.util.prefs.userRoot=<data/java> -Djava.util.prefs.systemRoot=<data/java>
  • Run: runtime/python/… -m baleen serve. The console window stays open showing the log; closing it stops Baleen. On a non-zero exit it waits for a key press.
  • Windows: chcp 65001; every path quoted (spaces and CJK).
  • Development: if runtime/ is absent (source checkout), fall back to python3 / py on PATH and say so.

14.4 Install (user steps)

  1. Copy the unzipped folder to a local disk, e.g. from the NAS or a USB drive.
  2. Double-click Start Baleen. The browser opens.
First run

macOS: a folder that arrived via browser download, AirDrop or e-mail is quarantined. Run once in Terminal: xattr -dr com.apple.quarantine "<folder>". On first access to a network volume, macOS asks whether Terminal may access it; choose Allow.

Windows: if the zip was downloaded, right-click it → Properties → Unblock before extracting. SmartScreen may still ask "Run anyway" for the .bat.

14.5 Uninstall

Quit Baleen and delete the folder.

  • Kept by design: output folders and their _baleen/ reports. They are the archival record.
  • Allowed traces outside the folder: the macOS privacy permission entry for Terminal (system-managed), and the browser's history and session cookie for 127.0.0.1.
  • Nothing else. AC-11 verifies this.

14.6 Build script

python scripts/build_bundle.py --platform win-x64 | mac-arm64 | mac-x64 [--version X.Y.Z] [--cache DIR]
  1. Read pins from scripts/runtimes.json: per component and platform, version, URL, SHA-256, archive type, extraction rule, license, source URL.
  2. Download to the cache and verify SHA-256; abort on mismatch. Checksums come from vendors' published checksum files where available; otherwise they are recorded at pin time in a reviewed PR.
  3. Python: extract the python-build-standalone install_only archive → runtime/python. Then pip install --no-deps --require-hashes -r requirements.lock, then pip install --no-deps ..
  4. FFmpeg:
    • Windows: pinned static GPL build (e.g. BtbN FFmpeg-Builds).
    • macOS: pinned static build (e.g. martin-riedl.de).
    • Copy ffmpeg and ffprobe only.
  5. LibreOffice:
    • Windows: msiexec /a <msi> /qn TARGETDIR=<abs>\runtime\libreoffice (administrative install: no registry or system changes).
    • macOS: hdiutil attach -nobrowse -readonly, ditto LibreOffice.app into runtime/, detach.
    • Pin archived release URLs (downloadarchive.documentfoundation.org).
  6. JRE: Temurin 21 JRE archive → runtime/jre, normalised so that runtime/jre/bin/java exists on both platforms.
  7. veraPDF: java -jar <installer>.jar scripts/verapdf-auto-install.xml (headless IzPack) → runtime/verapdf, CLI packs only.
  8. Records: write runtime/VERSIONS.json and THIRD_PARTY_NOTICES/; copy launchers, README.txt, LICENSE, NOTICE.
  9. Smoke test with the bundled runtime: baleen doctor (all tools found), then baleen convert on tests/fixtures/smoke. Statuses must match expectations.
  10. Zip.

17 · Decision records

Closed decisions

All records: status Accepted, 2026-10-05, decided by Czesio (Walking Whale) unless noted. DR-27 to DR-31 were added in v1.1, DR-32 to DR-37 in v1.2. To change one, add a new record that supersedes it; never edit history.

DR-01Scope: conversion and verification only
Decision
Baleen converts and verifies. Renaming to identifier schemes, cataloguing and metadata are out of scope.
Why
Naming rules are collection-specific and need human decisions; conversion and verification are generic and automatable.
Rejected
A combined rename + convert tool (scoped first, then cut).
DR-02Delivery: portable folder per OS, no installer, no signing
Decision
Zip per platform with all runtimes bundled; distributed by NAS, USB or GitHub Releases. Not code-signed.
Why
Zero install, uninstall by deletion, internal-first use. Signing costs money and maintenance: Apple US$99/yr plus notarisation, and a Windows OV certificate (Azure Artifact Signing is unavailable to Taiwan organisations). Not justified for v1.
Rejected
  • Electron/Tauri app: signing, size, nested-binary notarisation.
  • Browser-only app: Safari and Firefox lack folder access; no viable PDF/A conversion or validation in the browser.
  • NAS container: depends on the client's IT.
DR-03UI stack: Python + Starlette + Jinja2 + htmx
Decision
Server-rendered pages with htmx polling; no Node build step.
Why
One language end to end; offline; any browser works; stable, well-documented technology suits AI-assisted development.
Rejected
React/Vue SPA (second toolchain), NiceGUI (API churn), Streamlit (rerun model fights long jobs), Tk/Qt (look, size).
DR-04Read-only source; separate mirrored output
Decision
Outputs go to a user-chosen folder mirroring the source structure.
Why
Safety by construction: no rollback needed; undo = delete output.
Rejected
Writing next to originals (mixes old and new; risks the source).
DR-05Naming: keep stem, suffix only on clash
Decision
name.doc → name.pdf. On a clash, every party gets _<ext>. Clashes are computed over all supported files in the directory, regardless of settings.
Why
Familiar names for people; stable names across settings and re-runs.
Rejected
Always keeping the old extension (name.doc.pdf); writing beside the original.
DR-06Already-archival files: check and copy by default
Decision
copy_existing = true; the output becomes the complete normalised set. Setting allows check-only.
Why
One clean folder to hand over; every file in it has been verified.
Rejected
Check-only default (output would hold conversions only).
DR-07PDF/A: default 2b; existing PDFs not converted
Decision
  • New PDFs: 1b, 2b or 3b, the levels LibreOffice exports; default 2b.
  • Existing PDFs: any valid PDF/A flavour accepted. Non-PDF/A PDFs are flagged, not converted.
Why
2b is the common archival baseline and allows modern compression. Converting arbitrary PDFs needs Ghostscript (AGPL) and is error-prone.
Rejected
PDF/A-2u as default (LibreOffice cannot target it directly); bundling Ghostscript.
DR-08PDF/A validity only from veraPDF
Decision
Only a veraPDF compliant result counts as PDF/A. XMP claims never count.
Why
veraPDF is the reference open-source validator endorsed by the PDF Association; claims are cheap to fake or get wrong.
Rejected
Trusting the converter's PDF/A flag.
DR-09Unverifiable vs failed outputs
Decision
Outputs that fail a check are never placed. Outputs whose check could not run are placed but marked NEEDS_REVIEW.
Why
A missing validator is an environment problem, not a file problem. Placing the file keeps the work, and the flag keeps it honest.
Rejected
Blocking all PDFs when veraPDF is missing; silently passing them.
DR-10E-mail: HTML → LibreOffice; attachments extracted
Decision
Render headers and body to HTML and convert with LibreOffice. Attachments are saved and converted by default. Remote content is never fetched.
Why
Nothing is lost; no Chromium or Ghostscript in the bundle (size and AGPL); privacy (tracking pixels).
Rejected
Block-by-default (needs a human for every e-mail); list-only (drops content); Chromium print-to-PDF.
DR-11Audio-only output: .m4a by default
Decision
Audio goes into the MPEG-4 container with the .m4a extension. Setting allows .mp4 for strict "MP4 only" policies.
Why
Same container and codec as MP4, but players and catalogues recognise it as audio.
Rejected
.mp4 default (empty video windows); WAV/FLAC (out of target set).
DR-12Audio/video: copy when possible, otherwise H.264 + AAC
Decision
  • H.264/HEVC + AAC/MP3 streams are copied or remuxed.
  • Anything else is transcoded to x264 (CRF 18 high, CRF 23 standard) + AAC (192k / 128k).
  • No deinterlacing or scaling; odd dimensions are padded.
Why
Avoid generation loss where possible; maximise playback compatibility; keep the picture untouched.
Rejected
Lossless FFV1/Matroska (outside the target set); hardware encoders (inconsistent across OSes).
DR-13MP3 streams are copied, not re-encoded
Decision
MP3 audio is carried into MP4/M4A as-is.
Why
Re-encoding lossy to lossy loses quality for no archival gain. Revisit if R-11 finds playback problems.
Rejected
Always transcoding to AAC.
DR-14Text encoding: certain or ask
Decision
Only a BOM or strict UTF-8 counts as certain. Otherwise flag, unless the user picks an encoding.
Why
Mis-decoded text archived as truth is worse than a flagged file (P3).
Rejected
Heuristic charset detection (chardet-style guessing).
DR-15Fonts: system fonts only in v1
Decision
No bundled fonts; LibreOffice uses the machine's fonts and substitutes when needed.
Why
On Windows, system fonts (e.g. PMingLiU) give the closest match to how documents looked in Word. Bundling Noto CJK would make output identical across OSes, but further from the original.
Rejected
Bundled Noto CJK forced for consistency (revisit if cross-platform identity matters).
DR-16Images: never re-encode JPEG/TIFF
Decision
JPEG and TIFF are byte-copied. Others → JPEG q95 4:4:4, or TIFF LZW when alpha, high bit depth or CMYK. Multi-frame images are flagged.
Why
No generation loss; transparency, depth and colour model preserved where JPEG can't hold them.
Rejected
Everything → TIFF (huge); PNG as a target (outside the target set).
DR-17Fixity: SHA-256 everywhere
Decision
Hash every source and output; record both in the report.
Why
Standard archival fixity; enables resume and later audits.
Rejected
MD5 (weak); no hashing (no evidence).
DR-18Resume through prior reports
Decision
An existing output counts as done only if a prior report proves Baleen produced it from the same source bytes. Otherwise it is never overwritten.
Why
Safe restarts after crashes or cancels without trusting file names.
Rejected
Skip-if-exists (could skip unrelated files); overwrite (violates P2).

Rejected
Worker pools (revisit for large video batches).

Why
Completeness (P9) without noise; avoids hiding real content that merely starts with a dot.
Rejected
Silently skipping all hidden files.

DR-32Parallel lanes within user-set budgetsSupersedes DR-19
Decision
One job at a time, but items are processed in parallel across four lanes (Files, Documents, Media, PDF/A), within processor, memory and transfer budgets (§5.5). Python threads, not processes. Default: Balanced.
Why
Measured on the real tool chain (2 vCPU sandbox):
  • x264 already multi-threads (1.8×).
  • Pillow decoding and SHA-256 scale with threads (1.7×, 2.1×), because the heavy work runs in C outside the GIL.
  • LibreOffice start-up dominates (11×).
Sequential processing would leave most cores idle and take hours at the 20,000-file target. Threads behave the same on Windows and macOS.
Rejected
Sequential processing (DR-19); a multiprocessing pool (spawn and pickling complexity, no gain since the work is in C or child processes); unbounded parallelism (overloads laptops and shared NAS).
Decided by
Czesio, 2026-10-05; formulas by spec author
DR-33Work locally, publish atomically
Decision
Stage, convert and verify in a local work folder. Publish to the output as .part, read it back for V-HASH, then rename into place.
Why
Decoding, LibreOffice and veraPDF run against local disk, not SMB. Atomic placement (P5) and an honest V-HASH are kept.
Rejected
Staging inside the output root (v1.1; decodes over the network); skipping the read-back (weaker fixity).
DR-34Journal + index; CSV written at the end
Decision
Each run has a SQLite journal (standard library) that is both the crash-safe record and the UI index. The CSV is written in plan order when the run ends.
Why
Parallel items finish out of order; determinism (P7) and fast filtering at tens of thousands of rows.
Rejected
Appending the CSV out of order; in-memory results only (lost on crash).
DR-35Batch LibreOffice and veraPDF
Decision

  • veraPDF: up to 25 files per JVM, grouped by flavour.
Why
Process start-up costs 11× for LibreOffice (measured), and veraPDF reloads its profile per launch.
Rejected
One process per file (v1.1); a resident UNO listener (needs LibreOffice's bundled Python and a socket bridge; revisit if batching proves insufficient).

C. Glossary

Archival formatOne of the five targets: JPEG, TIFF, PDF/A, MP4, M4A.
WorkflowA registered job type (Convert, Check, …) with its own setup page (§12.8).
RunOne execution of a workflow: a run page, a report CSV and a run JSON.
PDF/A, flavourISO 19005 PDF for long-term preservation. 1b / 2b / 3b = parts 1–3, conformance level "b" (basic: reliable visual reproduction).
Copy · remux · transcodeByte copy of the file · streams copied into a new container · streams decoded and re-encoded.
CRFConstant Rate Factor in x264; lower = higher quality. 18 is visually near-lossless.
FixityEvidence that a file has not changed: here, SHA-256.
Work folder · stagingThe work folder is the local, Baleen-owned area where files are converted and verified. .baleen-staging/ in the output root holds .part files during publish.
Lane · budgetA lane is a queue of one kind of work (Files, Documents, Media, PDF/A). Budgets are the user-set limits on processor cores, memory and file transfers that all lanes share (§5.5).
veraPDFOpen-source PDF/A validator endorsed by the PDF Association.
SMB / NASWindows file-sharing protocol / network storage device serving it.
