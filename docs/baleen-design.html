UI / UX design · v1.1 · 2026-10-05

Baleen

by Walking Whale · Design

A quiet, precise workspace for archivists: choose two folders, press start, and get proof that every file is sound.

Approved for implementation Companion to Spec v1.2 Light theme Desktop-first walking-whale-baleen
TL;DR
  • A left rail groups the app into Workflows (Convert, Check, future ones), History (Runs) and System (Tools, Settings, About).
  • Every workflow uses one pattern: numbered setup cards and an action bar → a run page. The run page shows live progress, then becomes the results table. Clicking a file opens the side inspector.
  • Walking Whale tokens, plus one functional alert colour used only for FAILED. Status is always icon + text, never colour alone.
  • Bundled Inter, IBM Plex Mono and Cormorant Garamond; Lucide icons as an inline sprite. The logo comes later from a designer; until then, the wordmark (§04).
  • Users choose how much of their computer Baleen may use in Settings › Resource use: Gentle, Balanced or Maximum, with a live plain-language summary. They can also change it on the run page.
  • This doc has wireframes for every screen and state (§07), and a clickable prototype (§08) whose CSS is the production stylesheet.

01 · Design principles

Calm, legible, safe

DP1
Say what happens to the files

Every screen that can write anything says, in plain words, that the source folder stays untouched and where results go.

DP2
One pattern per job

Setup → run → results, identical for every workflow. Learn it once.

DP3
Problems first, never hidden

The few files that need a person sit at the top, each with a "What to do".

DP4
Paths are first-class

Monospace, copyable, the file name always visible. Archivists think in folders.

DP5
Quiet by default

Pearl and Abyss, generous space, one accent. Colour is reserved for status, and Biolum for signal.

DP6
Room to grow

New workflows, options and pages plug into the rail, the schema and the run page without a redesign.

Page anatomy

Every page has the same skeleton, so new pages inherit the layout:

  1. Breadcrumb (run pages only).
  2. Kicker (group name, in monospace).
  3. Title (Cormorant), then the rule accent.
  4. Description (one or two sentences).
  5. Page actions, right-aligned.
  6. Notices: tools missing, a run in progress.
  7. Content cards.
  8. Action bar, on setup pages only.

Setup pages are 960 px wide at most; run and history pages extend to 1,240 px.

Workflow extension contract (UI side)

A workflow module registers one object. The shell renders everything else.

WORKFLOW = {
  "id": "convert",                      # route /convert, run.workflow
  "name": "Convert",                    # rail label, page title
  "icon": "convert",                    # sprite id i-convert
  "order": 10,                          # rail position inside Workflows
  "description": "Turn legacy files into archival formats…",
  "folders": [                          # card ① fields, in order
     {"key": "source_dir", "label": "Source folder", "role": "read",  "help": "…"},
     {"key": "output_dir", "label": "Output folder", "role": "write", "help": "…"}],
  "options": SCHEMA,                    # card ② groups → fields (seg | switch | select)
  "preview": True,                      # card ③ present?
  "start_label": "Start converting",
  "confirm": True,                      # show the Start confirmation dialog
  "result_columns": ["status", "source", "output", "action", "reason"],
  "explainer": None                     # or a static card, e.g. Check's "What Baleen checks"
}

Option field schema: {key, label, help, type: seg|switch|select, values: [[value, label]…], default}. Segmented controls take 2–4 short values; select is for 5+ values or long labels; switch is for booleans.

05 · Iconography

Lucide, quietly

Lucide (ISC license), outline, stroke-width 1.75 at 18 px (16 and 14 for small contexts), currentColor. Icons ship as one inline sprite; use them as <svg class="ic"><use href="#i-name"/></svg>. An icon never appears without a text label or an aria-label.

08 · Hi-fi prototype

Click through it

A working model of the whole app. Settings › Resource use computes its summary with the exact spec §5.5 formulas for a simulated 8-core, 16 GB machine. It also has rail navigation, folder fields (Browse fills a sample path), options, Preview, Start → confirm → live run → results, filters, inspector (try ↑↓ and Esc), Cancel, Quit. Desktop notificationOpt-in (Settings). On finish: "Convert finished · 1,670 files · 8 to look at". Clicking it focuses the tab and opens the run.

Waiting & errors

  • Browse… While the OS dialog is open, the button shows a spinner and "Waiting for the folder dialog…", with a hint: "Don't see it? It may be behind this window." Cancelling the dialog changes nothing.
  • Preview uses an indeterminate bar and a running file count. Results replace it in place.
  • Pages are server-rendered and instant; there are no skeletons. Fragments (rows, inspector) swap without a spinner unless they take longer than 300 ms.
  • Errors stay close to their cause: field errors at the field, run errors as a notice on the run page, connection errors as the global banner. Toasts never carry errors.
  • One job at a time: while a job runs, the Start buttons are disabled and an info notice links to the run.
10 · Content & copy

Precise first, warm second

Voice

Second person, plain verbs, short sentences. Say what happens to the user's files. Never blame the user; never say "error" when "couldn't" will do.

Codes

Reason codes are for search and support. Show them in monospace chips, always next to a human label.

Reassure once

"Your source folder is never changed." appears on the Convert page and in the Start dialog, nowhere else.

11 · Accessibility

WCAG 2.1 AA, checked

  • Text contrast ≥ 4.5:1 and icons/focus ≥ 3:1 for every token pair in use (§03 table).
  • Status never relies on colour: icon + text label everywhere (D-13).
  • Every control is keyboard-operable with a visible focus ring; there are no hover-only actions.
  • Landmarks: nav (rail), main, aside (inspector, labelled "File details"); dialogs use role="dialog" + aria-modal + a labelled title.
  • Switches use role="switch" + aria-checked; segmented controls use pressed buttons in a labelled group; tiles that filter use aria-pressed.
  • The progress bar has role="progressbar" with values, and a polite live region (§09). Rail items get aria-current="page".
  • Tables use real <table> markup with header cells; the selected row has aria-selected.
  • Reduced motion is honoured; nothing flashes; spinners stop.
  • Text zoom to 200% keeps everything usable: the layout reflows to the drawer layout.
  • Collapsed rail icons carry aria-labels and tooltips.
  • Resource controls: the core meter has a text twin; stepper values are announced; the memory slider has aria-valuetext in GB; the plan summary is a polite live region.
